LÓGICA DE PROGRAMAÇÃO
INTRODUÇÃO

Quando comecei a conhecer a programação, percebi que, antes de aprender uma linguagem de programação, eu precisava aprender a pensar como um programador. Foi nesse momento que compreendi a importância da lógica de programação.

Eu posso definir a lógica de programação como a maneira de organizar meus pensamentos para encontrar soluções para diferentes problemas. Ela me permite dividir um problema em pequenas etapas e determinar uma sequência de instruções que devem ser realizadas para chegar a um determinado resultado.

Para mim, programar é semelhante a seguir uma receita. Quando quero preparar um prato, preciso seguir algumas etapas em uma determinada ordem: separar os ingredientes, preparar cada um deles e, depois, realizar o preparo. Se eu mudar a ordem de algumas etapas ou esquecer uma delas, o resultado pode não ser o esperado. Na programação, acontece algo parecido. O computador precisa receber instruções claras, organizadas e na sequência correta.

A lógica de programação também me ajuda a desenvolver o raciocínio lógico. Em vez de tentar resolver um problema de uma única vez, eu posso analisá-lo, identificar suas partes e encontrar uma solução passo a passo. Esse processo é importante porque os computadores não interpretam nossas intenções; eles apenas executam as instruções que recebem.

Um exemplo simples é imaginar um programa que precisa verificar se uma pessoa é maior de idade. Primeiro, eu preciso obter a idade da pessoa. Depois, comparo essa idade com 18. Se a idade for maior ou igual a 18, o programa poderá informar que a pessoa é maior de idade. Caso contrário, poderá informar que ela é menor de idade.

Nesse exemplo, estou utilizando uma estrutura de decisão. Esse é um dos conceitos fundamentais da lógica de programação. Existem também outros conceitos importantes, como variáveis, operadores, estruturas de repetição e algoritmos. Todos eles me ajudam a construir soluções cada vez mais completas.

Outro conceito fundamental é o algoritmo. Eu posso entender um algoritmo como uma sequência organizada de passos utilizada para resolver um problema ou realizar uma tarefa. Um algoritmo não precisa necessariamente estar escrito em uma linguagem de programação. Ele pode ser representado por textos, diagramas ou pseudocódigo.

Ao aprender lógica de programação, percebo que ela não serve apenas para criar programas. Ela também pode ser aplicada a situações do cotidiano, pois me ensina a analisar problemas, organizar informações, estabelecer prioridades e buscar soluções de maneira estruturada.

Por isso, considero a lógica de programação uma das bases mais importantes para quem deseja aprender a programar. Antes de ensinar o computador a executar uma tarefa, preciso saber exatamente o que quero que ele faça e quais passos serão necessários para alcançar o resultado. Quanto mais desenvolvo minha capacidade de raciocinar logicamente, mais preparado fico para transformar ideias e problemas em soluções por meio da programação.

FUNDAMENTOS

ALGORITMO: DA IDEIA A EXECUÇÃO 1. O que é um algoritmo? Poucos conceitos são tão fundamentais para a Ciência da Computação quanto o de algoritmo. Antes mesmo de escrever um programa, é necessário compreender como um problema pode ser descrito de maneira suficientemente precisa para que suas etapas de solução possam ser executadas por alguém — ou por uma máquina. Em termos gerais, um algoritmo pode ser entendido como uma sequência organizada e finita de instruções destinada à realização de uma tarefa ou à solução de um problema. Essa definição parece simples, mas contém algumas ideias importantes. Um algoritmo possui uma sequência de ações, essas ações precisam ser compreensíveis para quem as executará e, finalmente, sua execução deve produzir algum resultado. Embora hoje a palavra algoritmo esteja quase sempre associada aos computadores, algoritmos não são uma invenção da computação. Sempre que uma atividade pode ser descrita por meio de uma sequência organizada de procedimentos, encontramos, em alguma medida, uma estrutura algorítmica. Uma receita culinária é um exemplo bastante intuitivo. Para preparar determinado prato, seguimos instruções como misturar ingredientes, aquecer uma preparação, acrescentar determinado componente ou aguardar um intervalo de tempo. A sequência dessas ações conduz a um resultado previamente esperado. Uma partitura musical apresenta uma situação semelhante. O músico recebe informações sobre as notas, sua duração, intensidade e ordem de execução. Ao seguir essas instruções, produz uma determinada composição musical. Também podemos encontrar uma estrutura algorítmica em um manual de operação de um equipamento. Para realizar uma gravação, por exemplo, o usuário pode precisar selecionar um canal, inserir uma mídia, verificar determinadas condições e iniciar a gravação. Em todos esses casos existe uma relação fundamental: instruções → execução → resultado Essa relação está no centro da ideia de algoritmo. 2. Algoritmo e execução Um algoritmo, entretanto, não realiza uma tarefa por si mesmo. É necessário que exista algum agente capaz de executar suas instruções. Podemos chamar esse agente de processador. O processador não precisa necessariamente ser um computador. Em uma receita culinária, por exemplo, o processador pode ser uma pessoa equipada com os utensílios necessários para preparar o alimento. Em uma apresentação musical, pode ser o conjunto formado pelo músico e pelo instrumento. Em um sistema computacional, o processador é constituído pelos componentes capazes de interpretar e executar as instruções de um programa. Essa distinção é importante porque o mesmo algoritmo pode produzir resultados diferentes se o processador não possuir os recursos necessários para executá-lo. Imagine, por exemplo, uma instrução como: Aqueça o recipiente até atingir determinada temperatura. Essa instrução pressupõe a existência de um equipamento capaz de produzir e controlar calor, além de algum mecanismo que permita verificar a temperatura. Se esses recursos não estiverem disponíveis, a instrução não poderá ser executada adequadamente. Portanto, um algoritmo não deve ser analisado isoladamente. É necessário considerar também quem ou o que irá executá-lo. Podemos representar essa relação da seguinte maneira: Algoritmo + Processador → Processo → Resultado Chamaremos de processo a execução efetiva de um algoritmo. Assim, o algoritmo corresponde à descrição das ações, enquanto o processo corresponde à realização dessas ações. Essa distinção aparece constantemente na computação. Um programa armazenado em um computador pode permanecer inativo durante determinado período. Quando é iniciado, suas instruções passam a ser executadas e um processo é criado para realizar essa execução. 3. As características de um algoritmo Se qualquer sequência de ações pudesse ser considerada um algoritmo, o conceito seria pouco útil. É necessário estabelecer algumas propriedades que permitam distinguir um procedimento bem definido de uma simples descrição informal de ações. Uma primeira característica é a clareza. As instruções devem ser suficientemente precisas para que o processador saiba o que fazer. Uma instrução como “faça rapidamente” pode ser compreensível para uma pessoa em determinado contexto, mas é inadequada quando precisamos definir exatamente o comportamento de um sistema computacional. Uma segunda característica é a determinação da sequência de execução. Depois que uma instrução é realizada, deve ser possível identificar qual ação deverá ocorrer em seguida. Quando existem diferentes possibilidades, o algoritmo precisa estabelecer explicitamente quais condições determinam cada caminho. A terceira característica é a finitude. Um algoritmo deve possuir uma execução capaz de terminar. Não basta realizar ações indefinidamente; é necessário que, depois de uma quantidade finita de etapas, seja possível alcançar o resultado pretendido. Podemos resumir essas propriedades em três ideias: Precisão: as instruções devem ser claras e não ambíguas. Determinação: a sequência de execução deve ser definida, inclusive quando houver decisões. Finitude: a execução deve terminar após um número finito de etapas. Essas características não são meros detalhes formais. Elas são essenciais para que um algoritmo possa ser executado de maneira confiável. 4. Entrada e saída Existe ainda outro aspecto fundamental. Muitos algoritmos dependem de informações fornecidas antes ou durante sua execução. Essas informações constituem a entrada do algoritmo. Considere um algoritmo destinado a calcular a média de três números. Os três números fornecidos para o cálculo representam a entrada. Da mesma maneira, em uma receita culinária, os ingredientes disponíveis podem ser considerados dados de entrada. Em um sistema bancário, informações como número da conta, valor da operação e tipo de transação podem constituir entradas para determinados algoritmos. A entrada, portanto, representa aquilo que o algoritmo recebe para realizar seu trabalho. Ao final da execução, espera-se obter algum resultado. Esse resultado constitui a saída. No algoritmo da média, a saída será o valor calculado. Em uma receita, o resultado pode ser o alimento preparado. Em um sistema de processamento de dados, pode ser um relatório, uma mensagem, um valor calculado ou alguma alteração realizada em uma base de dados. Podemos então ampliar nosso modelo: Entrada → Algoritmo → Saída Essa representação simples é uma das formas mais importantes de compreender o funcionamento de sistemas computacionais. O algoritmo recebe determinados dados, realiza uma sequência de operações e produz um resultado. 5. Um algoritmo aparentemente correto Considere agora uma situação cotidiana. Suponha que alguém queira gravar um programa de televisão em uma fita e escreva as seguintes instruções: Selecione o canal desejado. Insira a fita no aparelho. Pressione a tecla REC. A sequência parece perfeitamente razoável. Entretanto, uma análise mais cuidadosa revela uma situação que não foi considerada. E se a fita já tiver sido utilizada e estiver parcialmente gravada? Nesse caso, o aparelho começará a gravação a partir da posição atual da fita. O resultado provavelmente não será aquele que se pretendia obter. O problema não está necessariamente nas instruções isoladamente, mas na ausência de uma consideração importante sobre a entrada. O algoritmo pressupõe que a fita esteja posicionada corretamente, mas essa condição não foi explicitada. Uma possível solução seria acrescentar uma etapa: Selecione o canal desejado. Insira a fita no aparelho. Rebobine a fita. Pressione a tecla REC. Agora surge outro problema. Se a fita já estiver no início, a operação de rebobinamento talvez seja desnecessária. Podemos melhorar o procedimento introduzindo uma condição: Selecione o canal desejado. Insira a fita no aparelho. Verifique se a fita está rebobinada. Se não estiver, rebobine-a. Pressione a tecla REC. O exemplo é simples, mas apresenta uma ideia essencial da construção de algoritmos: um algoritmo precisa considerar as situações que podem ocorrer durante sua execução. 6. Condições e tomada de decisão Nem sempre um algoritmo pode ser descrito como uma sequência linear de instruções. Em muitos problemas, uma ação depende do resultado de uma verificação anterior. Imagine um sistema que precise determinar se um aluno foi aprovado. Uma regra poderia ser: Se a média for maior ou igual a 60, o aluno está aprovado; caso contrário, está reprovado. O algoritmo possui agora dois possíveis caminhos. Média >= 60? / \ Sim Não / \ Aprovado Reprovado Esse mecanismo é chamado de estrutura condicional. As estruturas condicionais são fundamentais porque permitem que um algoritmo reaja de maneira diferente diante de diferentes entradas. É justamente essa capacidade que torna os algoritmos suficientemente expressivos para representar situações do mundo real. Nem todos os casos são iguais, e um procedimento precisa ser capaz de distinguir entre eles. 7. O algoritmo como uma transformação Podemos agora olhar para o conceito de algoritmo de uma maneira mais abstrata. Um algoritmo recebe uma determinada entrada, transforma essa informação por meio de uma sequência organizada de operações e produz uma saída. Podemos representar esse processo por: Entrada → Processamento → Saída O processamento é constituído pelas instruções do algoritmo. Essa visão é particularmente importante na Ciência da Computação porque permite separar três elementos que frequentemente aparecem misturados em problemas cotidianos: dados: aquilo que será utilizado pelo algoritmo; processamento: as operações realizadas sobre esses dados; resultado: aquilo que é produzido ao final. Considere, por exemplo, um algoritmo para calcular o valor total de uma compra. A entrada pode ser constituída pelos preços dos produtos e suas respectivas quantidades. O processamento consiste em multiplicar cada preço pela quantidade e somar os valores obtidos. A saída será o valor total da compra. Embora o problema seja simples, a estrutura permanece a mesma em aplicações muito mais complexas. Um sistema de comércio eletrônico, um programa de controle financeiro ou uma aplicação científica podem manipular milhões de dados e executar milhares de operações, mas continuam obedecendo ao mesmo princípio fundamental: receber informações, processá-las segundo regras definidas e produzir resultados. 8. Por que estudar algoritmos? A importância dos algoritmos não está apenas na capacidade de programar computadores. Estudar algoritmos significa aprender a organizar o pensamento para resolver problemas. Quando um problema é transformado em um algoritmo, é necessário identificar quais informações estão disponíveis, quais resultados são desejados, quais operações precisam ser realizadas e quais situações especiais podem surgir durante a execução. Esse processo exige precisão. Um ser humano pode interpretar uma instrução incompleta usando seu conhecimento e sua experiência. Um computador, por outro lado, não possui essa liberdade de interpretação. A instrução precisa ser apresentada dentro das regras que o sistema consegue compreender. Por isso, programar não consiste simplesmente em escrever comandos em uma linguagem de programação. Antes de escrever o programa, é necessário construir uma solução suficientemente precisa para o problema. A linguagem de programação é, nesse contexto, uma forma de representar o algoritmo para que ele possa ser executado por um computador. Podemos, portanto, estabelecer uma sequência conceitual: Problema → Solução → Algoritmo → Programa → Execução → Resultado O problema representa aquilo que desejamos resolver. A solução descreve uma estratégia para resolvê-lo. O algoritmo organiza essa estratégia em etapas precisas. O programa traduz essas etapas para uma linguagem compreendida pelo computador. A execução transforma o programa em ações efetivas, produzindo finalmente um resultado. 9. Uma primeira definição formal Depois dessas observações, podemos formular uma definição mais cuidadosa: Um algoritmo é uma sequência finita, ordenada e não ambígua de instruções que, a partir de uma determinada entrada, realiza um processamento e produz uma saída em tempo finito. Essa definição reúne os principais conceitos apresentados neste capítulo. Um algoritmo possui entrada, porque pode receber dados para serem processados. Possui instruções, porque precisa determinar as ações que serão realizadas. Possui uma ordem de execução, porque as ações não acontecem de maneira arbitrária. Possui condições, quando diferentes situações exigem diferentes caminhos. E possui uma saída, que representa o resultado produzido após o processamento. Além disso, sua execução deve ser finita e suas instruções precisam ser suficientemente precisas para que o processador possa realizá-las. Esses princípios constituem a base sobre a qual serão construídos conceitos mais avançados da Ciência da Computação. À medida que avançarmos, veremos que existem diferentes maneiras de representar um algoritmo, desde descrições textuais até estruturas gráficas e linguagens de programação. Também veremos que dois algoritmos podem resolver o mesmo problema de maneiras diferentes, utilizando quantidades distintas de tempo e memória. É nesse momento que o estudo de algoritmos deixa de ser apenas uma maneira de descrever procedimentos e passa a constituir uma das ferramentas centrais para compreender como problemas podem ser resolvidos de forma sistemática, eficiente e computável.

REPRESENTANDO ALGORITMO

Compreender um algoritmo é uma coisa; conseguir expressá-lo de maneira clara é outra. À medida que os problemas se tornam mais complexos, uma simples descrição em linguagem cotidiana deixa de ser suficiente. Torna-se necessário utilizar formas de representação que permitam visualizar a sequência de ações, as decisões envolvidas e as possíveis repetições. Existem diversas maneiras de representar um algoritmo. Entre as mais utilizadas estão a descrição textual, o fluxograma e o pseudocódigo. A descrição textual é a forma mais próxima da linguagem cotidiana. É adequada para apresentar uma ideia geral, especialmente quando o problema ainda está sendo analisado. O fluxograma utiliza símbolos gráficos para representar as diferentes etapas de um algoritmo. Ele permite visualizar o fluxo de execução e identificar pontos em que uma decisão ou repetição ocorre. O pseudocódigo, por sua vez, procura aproximar a estrutura de um programa de computador da linguagem humana. Embora não esteja necessariamente associado a uma linguagem de programação específica, ele permite representar algoritmos de maneira estruturada. Essas formas não competem entre si. Cada uma pode ser útil em uma etapa diferente do desenvolvimento da solução.

UM PRIMEIRO ALGORITMO

Considere um problema bastante simples: determinar a soma de dois números. Antes de pensar em uma linguagem de programação, podemos descrever a solução em termos de suas etapas fundamentais. Receber o primeiro número. Receber o segundo número. Somar os dois números. Apresentar o resultado. Temos aqui um algoritmo completo. Observe que ele possui uma entrada — os dois números — e uma saída — o resultado da soma. Podemos representá-lo por meio do seguinte pseudocódigo: Algoritmo SomaDoisNumeros leia número1 leia número2 resultado ← número1 + número2 escreva resultado FimAlgoritmo O símbolo ← indica uma atribuição. Nesse caso, significa que o valor obtido pela soma será armazenado na variável resultado. Essa representação introduz um novo conceito fundamental: a variável.

VARIÁVEIS: MEMÓRIAS PARA DADOS

Durante a execução de um algoritmo, frequentemente precisamos guardar informações para utilizá-las posteriormente. Uma variável pode ser entendida, inicialmente, como um espaço identificado capaz de armazenar um valor. Imagine uma caixa com uma etiqueta chamada idade. Podemos colocar dentro dela o valor 25. Em outro momento, podemos substituir esse valor por 26. A ideia de variável é semelhante. idade ← 25 Nesse momento, a variável idade passa a armazenar o valor 25. Posteriormente: idade ← 26 O valor armazenado passa a ser 26. É importante perceber que a variável possui um nome e, durante a execução do algoritmo, pode assumir diferentes valores. Podemos ter, por exemplo: nome ← "Mariana" idade ← 21 altura ← 1.68 aprovado ← verdadeiro Essas variáveis armazenam informações de naturezas diferentes. nome representa um texto, idade representa um número inteiro, altura representa um número real e aprovado representa uma informação lógica. Essa distinção nos conduz ao conceito de tipo de dado.

TIPOS DE DADOS

Um algoritmo precisa saber que tipo de informação está manipulando. Os tipos mais elementares encontrados em grande parte das linguagens de programação são: Inteiro: representa números sem parte fracionária, como 10, -3 e 250. Real: representa números que podem possuir parte fracionária, como 3.14 e 7.5. Caractere ou texto: representa símbolos e sequências de caracteres, como "Ana" ou "Ciência da Computação". Lógico: representa valores de verdadeiro ou falso. A existência de tipos não é apenas uma questão de organização. Ela permite determinar quais operações podem ser realizadas sobre cada informação. Podemos somar dois números: 10 + 5 Mas não faz sentido realizar uma soma aritmética diretamente entre: "João" + 5 A menos que a linguagem tenha alguma regra específica para essa operação. A definição adequada dos tipos de dados contribui para que o algoritmo seja mais claro e para que erros possam ser identificados antes ou durante sua execução.

OPERADORES

Para transformar os dados de entrada em resultados, os algoritmos precisam realizar operações. Os operadores aritméticos são utilizados para cálculos matemáticos. Entre os mais comuns estão: + soma - subtração * multiplicação / divisão Assim, podemos escrever: total ← preço * quantidade Se preço valer 20 e quantidade valer 3, a variável total receberá o valor 60. Além dos operadores aritméticos, existem os operadores relacionais, utilizados para comparar valores: > maior que < menor que >= maior ou igual <= menor ou igual = igual <> diferente Essas operações produzem um valor lógico: verdadeiro ou falso. Por exemplo: idade >= 18 será verdadeiro quando a idade for maior ou igual a 18. Essa possibilidade de comparar valores é fundamental para a construção de algoritmos que tomam decisões.

ESTRUTURAS CONDICIONAIS

Até este ponto, nossos algoritmos seguiram uma sequência linear. Cada instrução era executada depois da anterior. Na prática, muitos problemas exigem decisões. Considere a seguinte situação: Dado o valor de uma idade, informar se a pessoa é maior de idade. A solução pode ser descrita assim: Ler a idade. Verificar se a idade é maior ou igual a 18. Se a condição for verdadeira, informar que a pessoa é maior de idade. Caso contrário, informar que a pessoa é menor de idade. Em pseudocódigo: leia idade se idade >= 18 então escreva "Maior de idade" senão escreva "Menor de idade" fimse A palavra se introduz uma condição. O algoritmo deixa de possuir um único caminho de execução. Dependendo do valor da entrada, um caminho será escolhido. Podemos imaginar sua execução como uma bifurcação: idade >= 18? / \ sim não / \ "Maior de idade" "Menor de idade" Esse mecanismo é fundamental para a computação. Programas reais precisam tomar decisões constantemente: verificar se uma senha está correta, determinar se existe saldo suficiente, descobrir se um arquivo existe, identificar se uma temperatura ultrapassou determinado limite e assim por diante.

CONDIÇÕES COMPOSTAS

Uma condição também pode envolver mais de uma comparação. Imagine que uma pessoa só possa receber determinado benefício quando sua idade estiver entre 18 e 65 anos. Não basta verificar apenas uma condição. É necessário verificar duas: idade >= 18 e idade <= 65 Podemos combiná-las utilizando operadores lógicos. Os principais são: E OU NÃO O operador E exige que todas as condições sejam verdadeiras. idade >= 18 E idade <= 65 A expressão será verdadeira somente quando as duas comparações forem verdadeiras. O operador OU permite que pelo menos uma das condições seja verdadeira: pagamento = "pix" OU pagamento = "cartão" Já o operador NÃO inverte o valor lógico de uma condição. NÃO aprovado representa uma condição verdadeira quando aprovado for falso. Esses operadores permitem construir decisões mais elaboradas sem abandonar a estrutura fundamental dos algoritmos.

REPETIÇÃO: QUANDO UMA VARIÁVEL PRECISA SER REPETIDA VÁRIAS VEZES

Outro problema frequente ocorre quando precisamos executar a mesma operação repetidamente. Imagine um algoritmo que deve apresentar os números de 1 até 10. Uma solução poderia ser escrever dez instruções: escreva 1 escreva 2 escreva 3 ... escreva 10 Embora funcione, essa solução é pouco elegante. Imagine agora que fossem necessários os números de 1 até 1.000. Teríamos de escrever centenas de instruções. A solução adequada é utilizar uma estrutura de repetição. Por exemplo: para contador de 1 até 10 faça escreva contador fimpara A variável contador assume sucessivamente os valores de 1 a 10, e a instrução de saída é executada a cada repetição. Essa estrutura permite representar uma grande quantidade de operações por meio de poucas instruções. É uma das ideias mais poderosas da programação: uma instrução pode representar uma quantidade potencialmente grande de ações durante a execução.

REPETIÇÕES CONDICIONAIS

Nem sempre sabemos antecipadamente quantas vezes uma ação deverá ser repetida. Considere um sistema que solicita uma senha ao usuário. O sistema deve continuar solicitando a senha enquanto ela estiver incorreta. Nesse caso, a quantidade de tentativas não é necessariamente conhecida. Podemos escrever: leia senha enquanto senha estiver incorreta faça escreva "Senha incorreta. Tente novamente." leia senha fimenquanto escreva "Acesso permitido." A repetição depende de uma condição. Enquanto a condição for verdadeira, o conjunto de instruções continuará sendo executado. Esse tipo de estrutura aparece constantemente em sistemas computacionais: enquanto houver dados para processar, enquanto uma conexão estiver ativa, enquanto o usuário não escolher sair, enquanto determinada condição não for satisfeita.

A IMPORTÂNCIA DA ORDEM

A sequência das instruções é uma característica essencial dos algoritmos. Considere: a ← 10 b ← 20 soma ← a + b O cálculo de soma depende dos valores de a e b. Portanto, essas variáveis precisam receber seus valores antes que a soma seja realizada. Se invertermos a ordem: soma ← a + b a ← 10 b ← 20 o resultado poderá ser diferente ou até mesmo inválido, dependendo do ambiente em que o algoritmo for executado. Isso mostra que um algoritmo não é simplesmente um conjunto de instruções. É uma sequência estruturada de instruções. A ordem faz parte do significado. Essa característica parece evidente em exemplos simples, mas torna-se extremamente importante em algoritmos complexos, nos quais centenas ou milhares de operações podem depender umas das outras.

DO ALGORITMO AO PROGRAMA

Até aqui, estamos descrevendo soluções por meio de pseudocódigo. Mas como essas soluções chegam ao computador? Para que um computador execute um algoritmo, precisamos representá-lo utilizando uma linguagem de programação. Linguagens como Python, Java, C, C++, JavaScript e muitas outras fornecem regras para expressar algoritmos de forma que possam ser processados por um sistema computacional. Por exemplo, o algoritmo: leia dois números some os dois valores mostre o resultado poderia ser representado em Python como: numero1 = float(input("Digite o primeiro número: ")) numero2 = float(input("Digite o segundo número: ")) resultado = numero1 + numero2 print("Resultado:", resultado) O programa é uma implementação concreta do algoritmo. Essa distinção é importante porque algoritmo e programa não são sinônimos. Um algoritmo descreve uma solução de maneira independente, ou relativamente independente, da linguagem utilizada. Um programa é uma implementação dessa solução em uma linguagem específica. O mesmo algoritmo pode, portanto, ser implementado em diferentes linguagens.

UM MESMO PROBLEMA - DIFERENTES ALGORIMOS

Uma característica particularmente interessante da Ciência da Computação é que um problema pode possuir diversas soluções algorítmicas. Imagine que precisamos encontrar determinado valor em uma coleção de números. Uma solução simples seria examinar os elementos um por um, começando pelo primeiro, até encontrar o valor procurado. Outra solução poderia explorar alguma propriedade da organização dos dados para reduzir a quantidade de elementos que precisam ser examinados. As duas soluções podem produzir o mesmo resultado, mas podem apresentar comportamentos muito diferentes quando o tamanho da entrada aumenta. É nesse ponto que surge uma questão central: Não basta encontrar um algoritmo que funcione. Muitas vezes precisamos encontrar um algoritmo que funcione de maneira eficiente. Essa preocupação conduz ao estudo da complexidade de algoritmos.

CORREÇÃO E EFICIÊNCIA

Quando analisamos um algoritmo, pelo menos duas perguntas são fundamentais. A primeira é: O algoritmo produz o resultado correto? Essa é uma questão de correção. Um algoritmo que produz resultados incorretos não resolve o problema, mesmo que seja extremamente rápido. A segunda pergunta é: Quanto custa executar esse algoritmo? Aqui entram fatores como tempo de execução e quantidade de memória utilizada. Imagine dois algoritmos capazes de resolver o mesmo problema. O primeiro realiza 10 operações para uma determinada entrada, enquanto o segundo realiza 1.000. Para uma entrada pequena, talvez a diferença seja irrelevante. Entretanto, se o tamanho da entrada aumentar significativamente, essa diferença poderá se tornar decisiva. Por isso, a análise de algoritmos procura compreender como os recursos necessários para sua execução crescem à medida que o tamanho do problema aumenta.

O TAMANHO DA ENTRADA

Considere um algoritmo que precisa somar todos os elementos de uma lista. Se a lista possui cinco elementos, precisamos realizar poucas operações: 5 elementos → poucas operações Se possui um milhão de elementos: 1.000.000 de elementos → muito mais operações Podemos então perguntar: Como o número de operações cresce em relação ao tamanho da entrada? Essa pergunta está no centro da análise de complexidade. Em muitos casos, não estamos interessados no número exato de operações, mas na forma como esse número cresce.
